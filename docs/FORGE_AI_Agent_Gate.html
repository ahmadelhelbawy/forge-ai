FORGE — Architecture & Specification Gate

AI Prompt Specialist + Intent & Context Compiler

A reusable reference for understanding, observing, extending and building AI agents. FORGE is not “an LLM with a textbox.” The model is the reasoning engine; FORGE is the system around it: state, context, compiler logic, target knowledge, provenance, evaluation, memory and UX.

Product Contract

Human intent → structured understanding → justified context → target-aware prompt artifact → iterative refinement.

  • Accept a one-line task, a messy idea dump, or a long professional specification.
  • Create, improve, critique, revise, compare, merge and restore prompts conversationally.
  • Adapt output to the selected target: Claude Code, Codex/GPT, OpenCode, Kiro, Generic, future agents.
  • Prompt length is task-dependent. Optimize for effectiveness, fidelity, structure, clarity and token efficiency.
  • Execution of downstream coding agents is outside FORGE; FORGE prepares excellent instructions/context for them.

Non-Negotiable Core

Task IR Deterministic Compiler Target Profiles Provenance Trust Boundaries Context Discipline Strategies Diagnostics
  • LLMs may reason and generate, but deterministic invariants remain code-owned.
  • Provenance is assigned by FORGE, never trusted because a model claims it.
  • Repository/external context never silently becomes authoritative user instruction.
  • Semantic artifacts remain separate from volatile run metadata.

Agent / AI Tool Build Gate

Before building any new AI agent, answer these. If the answers are vague, architecture is not ready.

What is deterministic and what belongs to the LLM?
What is the agent state and who owns it?
What tools can the agent call, and with what permissions?
What context is authoritative, semi-trusted or untrusted?
How are prompts/artifacts versioned and restored?
How do we retrieve context without dumping everything?
How is behavior evaluated beyond mocked tests?
What is the smallest real user acceptance test?
What happens when the model/provider changes?
What technology can be omitted to keep the system shippable?
